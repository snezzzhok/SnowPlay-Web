# SnowPlay — браузерная сцена и прямые действия

Дата: 13 ноября 2026. Публичная версия: **https://snezzzhok.github.io/SnowPlay-Web/**. Репозиторий: **https://github.com/snezzzhok/SnowPlay-Web**. GitHub Pages развёрнут из `main`, корень репозитория. [Успешная публикация](https://github.com/snezzzhok/SnowPlay-Web/actions/runs/43519119121).

## Реализовано

1. В рабочей папке обнаружен существующий нативный SnowPlay. Самостоятельной браузерной сцены не было. Создана лёгкая HTML/CSS/Canvas-сцена с собственным пультом; нативный сервер не нужен посетителям Pages.
2. Подключены 23 SVG из библиотеки. Относительные пути работают под `/SnowPlay-Web/`; реестр содержит SHA-256. Проверены анонимные HTTP-запросы ко всем файлам и совпадение хешей, холодный запуск и перезагрузка WebKit, публичный запуск в гостевом Chrome. Конкретное имя «пропавшей картинки» в запросе не указано: проверены все картинки новой страницы. Старые API-адреса `/assets/<id>` не являются статическими файлами GitHub Pages.
3. Полёт Санты идёт по плавной дуге с разгоном, торможением, наклоном по касательной и покачиванием. Снегоуборщик имеет независимое состояние; тест сравнивает его положение и вращение колёс с Санта-сценой и без неё на каждом шаге. Маршруты колёс, машины и очистки снега согласованы.
4. Йети исключён из активной сцены и пульта обеих версий. Прямое падение ёлки и снежок с разрушением снеговика защищены от повторного старта. В нативном приложении старые поля/ресурсы и безопасные старые API-команды сохранены для совместимости. Автоматический Йети отключён в валидации конфигурации.
5. Новые и сброшенные настройки нативной версии: снег 35%, окна без снега и инея. Явные сохранённые предпочтения старого профиля сохраняются до пользовательского сброса. В браузере также сразу снег 35% и чистое демонстрационное окно.
6. Браузерный benchmark измеряет интервалы rAF, CPU-время шага/рисования, p95/p99, максимальный интервал и совместную нагрузку. Есть экспорт JSON. Отдельный экран телефона не синхронизируется с компьютером.

Повторный прогон выявил потенциальную гонку: окончательное удаление ёлки сохранялось с задержкой до 500 мс, и при немедленном reload могло восстановиться прежнее состояние. Запись перенесена в кадр завершения. WebKit-fixture теперь перезагружает страницу сразу после исчезновения объектов и проверяет сохранённый флаг в том же кадре. Превью HTML также явно декодируются перед сообщением готовности, как и растры сцены. Экспорт добавляет ключ версии к адресам CSS/JS и SHA-256 к адресам изображений, чтобы обновлённая страница Pages не импортировала старые модули из кеша. Манифест запрашивается с `cache: no-store`.

## Измерения

Реальный **Apple M1**, Chrome **Guest**, публичный GitHub Pages, одна вкладка, энергосбережение macOS включено. Измерялся прямоугольник сцены **810×661 CSS px, DPR 2**, максимум **1460 снежинок**. Две секунды прогрева плюс 24 секунды измерения, фиксированное зерно 2027. По 1441 интервалу, 1414 из них — одновременно снег + Санта + машина. Изменения системного режима питания не выполнялись.

| Показатель | Исходный способ рисования | Итоговый |
|---|---:|---:|
| Средний FPS | 60,00 | 60,00 |
| Средний интервал rAF | 16,667 мс | 16,667 мс |
| p95 интервала | 17,6 мс | 17,6 мс |
| p99 интервала | 17,7 мс | 17,7 мс |
| Максимальный интервал | 17,8 мс | 17,8 мс |
| Интервалы >25 мс | 0 | 0 |
| Среднее CPU-время шага и рисования | 1,624 мс | 1,371 мс |

Исходные выгрузки через кнопку самой страницы: [chrome-baseline.json](chrome-baseline.json), [chrome-final.json](chrome-final.json). В измеренном прогоне CPU-время снизилось примерно на 16%; FPS остался 60. Это короткое сравнение одного устройства и браузера, без статистического доказательства эффекта на всех устройствах. Исходный вариант — первоначальный Canvas-рендер новой браузерной сцены, а не нативное приложение до всей доработки.

Первая попытка объединить частицы в большие контуры оказалась хуже: 4,824 мс против 1,440 мс в видимом WebKit. Вариант с кешированными картинками точек также не дал выигрыша. Эти варианты удалены из рабочей сцены; оставлены компактные круглые частицы, сгруппированы только изменения цвета/прозрачности Canvas. Дополнительно сокращены повторные записи позиции кнопки подарка в DOM; изображения подготавливаются один раз, временные объекты ограничены, скрытая вкладка останавливается. Промежуточные данные сохранены в `browser-scene-first-pass.json` и `browser-scene-sprite-pass.json`.

Видимый WKWebView на том же Mac с энергосбережением показал около **30 FPS**, интервал **33,33 мс**, при небольшом CPU-времени. Это согласуется с ограничением частоты браузером/энергосбережением, но причинность отдельно выключением режима не проверялась. [Документация WebKit об управлении частотой](https://webkit.github.io/explainers/animation-frame-rate/) описывает влияние энергосбережения и температуры. Прогон WebKit и проверка адаптивной вёрстки: [browser-scene-result.json](browser-scene-result.json).

**Физический телефон не тестировался.** Мобильное окно 390×844 на Mac проверяет только вёрстку и картинки. GPU-время, длительный тепловой режим и частота представленных дисплеем кадров не измерялись. До появления реального телефонного замера критерий «60 FPS на телефоне» не принят.

Финальный контроль после исправлений reload/кеша: [chrome-release-check.json](chrome-release-check.json), [скриншот релиза](pages-release-live.png). Та же опубликованная сцена снова показала 60 FPS под совместной нагрузкой; точные p95 и CPU-значения находятся в этой отдельной выгрузке. Проверка готового экспорта с версионными адресами: [browser-release-smoke.json](browser-release-smoke.json).

## Проверки

- Семь Node-тестов: defaults/валидация, одновременная работа Санты и машины, повторные команды, непрерывность дуги, попадание/сугроб, вертикальное стряхивание, первое открытие подарка.
- Видимый WebKit-fixture: все 23 ресурса и HTML-картинки на первом открытии и reload, сохранение настроек, сброс, многократные команды, корректная вёрстка на ширине 390 px.
- Гостевой Chrome: публичная страница без входа в GitHub, экспорт обоих замеров, реальное нажатие падения ёлки и броска, восстановление через сброс. [Скриншот](pages-chrome-live.png).
- Нативная debug-сборка; 58 методов ядра с 0 ошибками через локальный XCTest-адаптер; asset-интеграция; WebKit-пульт и сохранение после рестарта; токены/Origin/Host/ошибочные запросы локального API.
- Новый нативный fixture: повторные команды, падение без персонажа, заметная дуга снежка, фрагменты в снежный запас, отмена сценок при паузе/сбросе. [Результат](direct-actions-result.json).

## Ограничения и ручная проверка

Браузер не рисует поверх системных окон macOS. Здесь демонстрационное окно внутри страницы; нативное приложение остаётся отдельным. GitHub Pages — [статический хостинг HTML/CSS/JS](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages); общей сессии нескольких устройств у этой версии нет.

Полный порядок ручной проверки и получение настоящего телефонного результата: [Browser-Public-Version.md](Browser-Public-Version.md). Нативная сборка предназначена для arm64 macOS 13+, имеет ad-hoc подпись; Developer ID и нотариализация не выполнялись. Долгосрочная стабильность и все комбинации Spaces/полноэкранных приложений в этом проходе не проверялись.
