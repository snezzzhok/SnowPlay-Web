# ❄︎ SnowPlay — Web и macOS

**Браузерная версия:** [открыть SnowPlay](https://snezzzhok.github.io/SnowPlay-Web/) · [исходники](https://github.com/snezzzhok/SnowPlay-Web) · [запуск и проверки](Docs/Browser-Public-Version.md).

Нативная редакция **Living Winter World**: снег с массой, гномы с машиной, доставка ёлки, ручные активности Йети и Snow Duel. По умолчанию снег умеренный, размер хлопьев 2,5×, окна чистые; снегопад идёт за рабочими окнами. Сюжетные сценки запускаются кнопками, автоматического Санты нет.

[Отчёт Living Winter и ограничения проверки](Docs/Living-Winter-Report.txt) · [контрольные кадры](Docs/Living-Frames) · [результат нативных сцен](Docs/living-native-result.json).

Ранее опубликованная самостоятельная браузерная сцена описана в [отдельном отчёте](Docs/Browser-Public-Version.md). Этот выпуск обновляет нативное приложение macOS.

Предыдущая редакция: [Нижний зимний мир](Docs/Floor-World-Revision.md). [Анимация нативных сценариев](Docs/floor-native-preview.gif), [MP4](Docs/floor-native-preview.mp4), [вид пульта](Docs/floor-panel-live.png).

## Что находится в репозитории

- Корневые `index.html`, JS/CSS, `assets/`, `web-tests/` и `checks/` — существующая публичная браузерная сцена. Её рабочие файлы сохранены.
- `Sources/`, `Tests/`, `Package.swift`, `SnowPlay.xcodeproj/`, `Scripts/` — нативное macOS-приложение.
- `dist/SnowPlay-macOS.zip` — готовая локальная сборка macOS с подписью ad-hoc.
- `LegacyAssets/` — архив первоначальных моделей. Это имя не конфликтует с браузерной папкой `assets/` на macOS.
- [Инструкции браузерной версии](Docs/Browser-Repository-README.md). `npm test` запускает её тесты; `swift test` — тесты нативного ядра.

## Запуск macOS-приложения

Готовый архив приложения сохранён прямо в репозитории: [SnowPlay-macOS.zip](dist/SnowPlay-macOS.zip), [SHA-256](dist/SHA256SUMS.txt). На странице ZIP нажмите **Download raw file**, распакуйте архив и перенесите `SnowPlay.app` в Applications. Репозиторий публичный: скачивание доступно без входа в GitHub.

После локальной сборки приложение находится в `dist/SnowPlay.app`. Распакованный app и промежуточные файлы сборки в Git не включаются. Обычный **Code → Download ZIP** скачивает весь проект, а отдельный ZIP выше содержит готовое приложение.

```sh
open dist/SnowPlay.app
```

Нажмите снежинку в строке меню: откроется компактный пульт. Правый клик открывает дополнительное меню; **Open Control Panel…** также открывает пульт. Сервер работает на `127.0.0.1` со случайным портом; браузер можно закрыть, эффекты продолжают работать. Автозапуск не добавляется. Сборка arm64, macOS 13+, подпись ad-hoc; Developer ID/нотариализация не выполнялись.

Для точной геометрии чужих окон и шапочек Dock нужен **Accessibility**: меню **Enable Window Accessibility…**, затем разрешение в System Settings → Privacy & Security → Accessibility. Для самого рисования снега дополнительное разрешение не нужно. Приватные API не используются.

## Управление

Нативный пульт содержит пять вкладок:

- **Snow:** количество, скорость, стрелка ветра 180°, необязательный снег на окнах, стряхивание, снегоуборщик, Санта, подарок и режимы Focus/Balanced/Play. На Dock снега нет.
- **Tree:** выбор места, доставка за 6,5 секунды машины с гномом, три размера, звёзды/шарики/гирлянды, три крепления игрушек, подарки и удаление Йети с топором.
- **Snowman & Yeti:** ручная лопата, до пяти независимых снеговиков, сбор снежков из сугроба и бросок жестом; разрушение настоящим снежком, сюрприз, уклонение, кормление.
- **Duel:** по пять HP, угол и сила курсором, пять секунд на ход, физические столкновения, две сценки эвакуации; Escape завершает игру.
- **Lights:** крепления, провисание, палитры, мягкий свет, несколько нитей, удаление выбранной и шапочки Dock.

Настройки сохраняются в `~/Library/Application Support/SnowPlay/settings.json`. Старые данные ручных проверок сохраняются отдельно для совместимости; в компактном пульте чек-лист и сброс настроек скрыты.

## Сборка и ресурсы

В исправной среде Xcode/Swift 6:

```sh
swift build
swift test
Scripts/package.sh
```

На этой машине неполный/несогласованный CLT, поэтому используется локальный VFS-обход внутри `.build`:

```sh
Scripts/local-build.sh build
Scripts/test-core.sh
SNOWPLAY_LOCAL_TOOLCHAIN_WORKAROUND=1 Scripts/package.sh
```

`test-core.sh` выполняет те же **81 метод** через assertion-адаптер; это не запуск XCTest. Полный `xcodebuild test` здесь не выполнялся. Проект Xcode сохранён; неактивные шаблоны CI находятся в [Docs/CI-Templates](Docs/CI-Templates).

Сохранены 63 оригинальных SVG и исходный манифест библиотеки. World-реестр содержит 63 собственных/производных дополнения; старый замок остаётся неиспользуемым архивным ресурсом. Всего 126 зарегистрированных ресурсов, 131 подготовленных источников текстур 1×/2×, 30 компонентов персонажей и машины в двух общих атласах 1024×1024. Каталог ресурсов не используется для вырезания спрайтов; конвертации SVG на кадре нет.

```sh
python3 Scripts/prepare-floor-art.py
python3 Scripts/prepare-living-art.py
python3 Scripts/prepare-assets.py
python3 Scripts/prepare-assets.py --check
python3 Scripts/generate-xcode-project.py
```

Текущие компоненты создаёт `Scripts/prepare-living-art.py`, атласы собирает `Scripts/pack-character-atlas.py`, каталог пульта строится из манифестов. Оригинальные SVG сохранены, производный ствол ёлки отделён от неподвижной тени.

## Проверки

```sh
Scripts/test-core.sh
Scripts/test-living-native.sh
python3 Scripts/test-local-api.py
# После разблокировки Mac:
python3 Scripts/performance-living.py
python3 Scripts/test-window-effects.py
```

`test-living-native.sh` проверяет настоящие AppKit/SpriteKit-контроллеры в изолированной собственной сцене: 20 доставок/удалений ёлки, контакт с рукой, сборку/разрушение снеговика, подарок без Санты, обе концовки дуэли, 20 выходов, сюрприз и кормление. Кадры сохраняются в `Docs/Living-Frames`; содержимое чужих окон не захватывается.

Для изолированной видимой проверки на активном Mac: `python3 Scripts/build-live-mac-check.py`, затем `SNOWPLAY_RESOURCE_ROOT="$PWD/Sources/SnowPlay/Resources" .build/SnowPlayLiveCheck.app/Contents/MacOS/SnowPlayLiveCheck --config "$PWD/.build/live-manual-settings.json"`. Тест завершается через 120 секунд или кнопкой «Завершить»; `--panel` проверяет нативный пульт. Эти команды не используют обычный файл настроек.

Панель WebKit проверяется через `Scripts/WebPanelCheck.swift` и `Scripts/test-web-panel.py`; проверки окон используют `Scripts/WindowFixture.swift`. После разблокировки прошли живые переходы собственного NSWindow (move/resize/minimize/restore/close), настоящий обработчик menu bar → NSPopover и ввод Space/клик/drag в собственной видимой сцене. Это не проверка всех сторонних приложений и прозрачного настольного ввода. Живые native callbacks менялись примерно от 40 до 60/с; стабильные 60 FPS и presented GPU timestamps **не подтверждены**. Отдельный bitmap CPU-work также не является временем показанного кадра. См. `Docs/Living-Winter-Report.txt`, `Docs/living-live-performance.json` и `Docs/living-visible-preview.json`.

Нельзя гарантировать нулевую задержку публичной геометрии или произвольный порядок слоёв между чужими окнами. Для неоднозначной геометрии применяется безопасное скрытие. Полная приёмка нескольких физических дисплеев, Spaces, Stage Manager и Mission Control на текущем проходе не выполнялась.

## Приватность и история

Нет аккаунтов, аналитики, захвата содержимого экрана самим приложением, чтения документов или записи клавиш/звука. Используются метаданные геометрии окон и курсор для включённых эффектов. Локальный HTTP проверяет Host/Origin/сессионный токен и размеры запросов; внешних сетевых сервисов в приложении нет.

Предыдущие материалы сохранены как история: [Interactive Winter World](Docs/Interactive-Winter-World.md), [исследование референсов](Docs/Reference-Research/Analysis.md), [интеграция ассетов](Docs/Asset-Integration-Report.md), [платформенные ограничения](Docs/Feasibility.md). Текущее ТЗ Living Winter имеет приоритет над историческими сценариями Dock/площадки и выпуском без Йети.

Последняя версия пульта — на английском: Snow / Tree / Snowman / Duel / Lights. Убраны Reset, More, ручной чек-лист, статистика и переключатель автоматической сборки. Настройки и прежний локальный API совместимы; данные старых ручных проверок не удаляются.

Build a snowman включает ручную лопату на нижнем снегу. Удерживай кнопку мыши и катай три шара; они растут за счёт реальной массы сугроба и затем складываются в снеговика. Завершение возвращает обычный курсор, Escape отменяет лепку и возвращает массу незавершённых шаров. Временный слой лепки расположен над Dock/окнами, после завершения удаляется. Ёлка по-прежнему выбирается курсором с превью. Дуэль: курсор задаёт угол/силу, клик бросает снежок, ход 5 секунд.

Проверка ручной лепки без зависимости от блокировки экрана: `python3 Scripts/test-shovel.py` (реальные Cocoa-события в собственном контроллере с подготовленным снегом; не физический жест на рабочем столе). `Docs/shovel-result.json` и `Docs/simple-panel-check-result.json` содержат точный scope последних проверок.

После разблокировки выполнен и видимый проход CUA в отдельном профиле с естественным накоплением снега: Build a snowman → ввод drag → готовая трёхкомпонентная модель и автоматическое завершение. Scope и результат: `Docs/shovel-live-result.json`.


Доработка механик 14 ноября 2026: до пяти сохраняемых снеговиков; радиус лепимого шара до 26 pt, высота готовой модели до 96 pt. Snowman → Roll & throw включает сбор снега движением курсора; зажать шар, резко переместить мышь и отпустить — бросок. Move snowmen позволяет переместить любую модель даже при открытых рабочих окнах. Done/Esc закрывает интерактивный слой. Подсказки о лепке остаются в пульте. Йети виден на отдельном пропускающем клики слое во время ручных сцен; его бросок летит 1,3 с. Доставка ёлки длится 6,5 с, машина и гном уходят в разные стороны.

Проверки и ограничения именно этой доработки: [Mechanics-Report.txt](Docs/Mechanics-Report.txt), `Docs/mechanics-result.json`, `Docs/mechanics-live-result.json`. 79 методов ядра прошли. Программная Cocoa-проверка ввода не заменяет физический клик на рабочем столе; после разблокировки Mac физические клики/drag в собственной видимой сцене также прошли. Подробности: `Docs/mechanics-physical-input-result.json`. Выбор свободного участка рабочего стола и presented GPU frames этим тестом не подтверждаются.


Оптимизация для слабого Mac (14 ноября 2026): кэш Dock/статических слоёв/свечения гирлянд, слежение за окнами по необходимости, ускорение пула и broad phase частиц, адаптивная частота неподвижного фона. На Apple M1 в одинаковых последовательных сценариях CPU процесса снизился примерно на 78% без снега и на 39% при 1136 снежинках. Существенной экономии RAM не подтверждено. Методика и ограничения: [Optimization-Report.txt](Docs/Optimization-Report.txt), исходные данные `Docs/optimization-summary.json`. Настройки пользователя сохранены.
